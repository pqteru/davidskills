# Document Persistence

- Prefer updating SkillDocs over long chat summaries.
- After meaningful implementation steps, update `task.md` (and `test.md` / `verification.md` when the contract requires).
- Raw command output and traces belong in `verification.md`, not compressed into `task.md` alone.
- Keep each SkillDocs markdown artifact **under 600 lines** when practical so future sessions can reload cleanly (implementation source files are exempt).
